\section{Introduction}
\label{sec:intro}

Instruction following evaluation has become central to developing practical AI systems
capable of understanding and executing natural language commands.  Early benchmarks such
as IFEval \cite{zhou2023ifeval} established a standardised framework for measuring how
well models can follow instructions in English, but they quickly revealed a critical
limitation: the lack of multilingual coverage. M‑IFEval \cite{li2025xifbench}, XIFBench
\cite{he2024multi}, and Multi‑IF \cite{he2024multi} have since expanded the scope to
include 3, 6 and 8 languages, respectively. Marco-Bench-MIF \cite{zeng-etal-2025-marco}
extended the work to a commendable 30 languages, but these efforts are still limited to
a small subset of the world’s languages.

To bridge this gap, we introduce \textbf{MultiIFEval}, a benchmark that expands IFEval
to 305 target languages. Leveraging a large language model, we both translate and
localise every English prompt–response pair into each language, with localised grounding
coming from Wikipedia articles in the given language. The resulting dataset spans
high‑resource languages like Spanish and Mandarin as well as low‑resource ones such as
Xhosa and Quechua, providing an unprecedented testbed for multilingual instruction
following.

In addition to automated translations, we provide a manually translated Danish subset
curated by native speakers and validated by experts. This dual approach allows us to
quantify the impact of translation quality on model performance—an aspect largely
unexplored in prior work. Similar manually translations and localisations have been done
for Estonian \cite{dorkin2025ifeval-et} and French \cite{alhajar2024ifeval-fr} as well,
which we also include in our analysis.

Our main contributions are as follows:

\begin{itemize}
\item We create a multilingual instruction‑following benchmark spanning 305 languages.
\item We provide a manually translated and localised Danish subset for expert validation
  and comparison with machine translations.
\item We analyse the model performance discrepancies of the machine translated and
  manually translated versions of the Danish, Estonian and French versions of the
  dataset.
\item We evaluate XXX models on all 305 languages of the dataset.
\end{itemize}


\section{Dataset Generation}
\label{sec:dataset-generation}

The MultiIFEval dataset is generated via prompting a large language model in a zero-shot
fashion, for each sample of IFEval. The prompt contains both the instruction to
translate and localise each English sample. To reduce the risk of hallucination when
localising the examples, as well as to increase the quality of the translations, we
include for each IFEval sample a randomly chosen Wikipedia page in the target language.
We use structured generation to ensure that the output is of the correct format. The
full prompt can be found in Figure~\ref{fig:prompt}.

The structure of the generated \texttt{kwargs} deviate from the input \texttt{kwargs},
and the reason for this is that the language model we used for generation did not
support dictionaries as values in the JSON schema used in structured generation, so the
is merely a rephrasing of the keyword arguments to obey this constraint.

\section{Experiment Setup}
\label{sec:evaluation}

We evaluate a range of language models on MultiIFEval to assess instruction-following capabilities across languages. Our evaluation focuses on decoder-only models, which represent the dominant architecture for instruction-following tasks, while including encoder models for comparative analysis.

\paragraph{Models}
We evaluate multiple decoder-only models, including Llama-3.1-8B variants and other open-weight models of comparable scale. For comparison, we also include encoder-based models to examine architectural differences in multilingual instruction following. All models are evaluated in a zero-shot setting without task-specific fine-tuning.

\paragraph{Evaluation Approach}
Each model is evaluated on each language variant of MultiIFEval using zero-shot instruction following. Models receive instructions in the target language and must generate responses that satisfy the specified constraints. We do not provide examples or demonstrations, ensuring evaluation measures inherent multilingual capabilities rather than in-context learning.

\paragraph{Metrics}
Following the original IFEval methodology, we measure constraint satisfaction using binary pass/fail scoring per instruction. A model receives a pass only if its response satisfies all constraints specified in the instruction. We report both per-instruction accuracy and aggregate scores across constraint types.

\paragraph{Cross-lingual Analysis}
Our analysis examines performance patterns across language families, writing systems, and resource levels. We compare high-resource languages (e.g., French, German) against low-resource languages (e.g., minority African and Indigenous languages) to identify disparities in model capabilities. We also analyze whether performance correlates with language family membership or geographical proximity.

\paragraph{Comparison with MultiWikiQA}
As optional analysis, we examine correlation between MultiIFEval performance and MultiWikiQA scores, using the latter as a proxy for general language understanding. This comparison helps distinguish instruction-following specific capabilities from broader multilingual competence.

\section{Comparison of Machine vs Manual Translations}
\label{sec:comparison}

A key question in multilingual benchmark construction is whether machine translation produces evaluation datasets comparable to manual human translation. We analyze quality differences between our machine-translated datasets and manually-translated variants across three languages: Danish (our new manual translation), Estonian \cite{dorkin2025ifeval-et}, and French \cite{m-ifeval2025naacl}.

\paragraph{Manual Validation Methodology}
For Danish, we conduct expert validation comparing machine-translated and manually-translated instructions. Native Danish speakers with expertise in NLP evaluate both versions for: (1) naturalness and fluency, (2) preservation of constraint semantics, (3) cultural appropriateness of localized content, and (4) overall usability for evaluation purposes. Validators rate each instruction on Likert scales and provide qualitative feedback on problematic cases.

\paragraph{Cross-language Analysis}
We reference existing manual evaluations of Estonian \cite{dorkin2025ifeval-et} and French \cite{m-ifeval2025naacl} IFEval variants to contextualize our Danish findings. While each manual translation employed slightly different validation protocols, all three provide expert assessment of machine translation quality for instruction-following benchmarks.

\paragraph{Expected Analysis}
Our analysis will examine whether machine translation introduces systematic biases or errors that affect evaluation validity. We will compare model performance rankings on machine-translated versus manually-translated datasets to assess whether translation method affects relative model comparisons. We hypothesize that machine translation performs adequately for high-resource languages but may introduce artifacts in low-resource languages or for culturally-specific content.

\section{Conclusion}
\label{sec:conclusion}

We present MultiIFEval, an instruction-following benchmark spanning 305 languages, enabling evaluation of multilingual models at unprecedented scale. Our dataset combines machine-translated coverage across all languages with manually-translated, expert-validated variants for selected languages.

MultiIFEval addresses a critical gap in multilingual NLP evaluation by providing standardized instruction-following assessment across diverse languages and writing systems. We expect this resource to support research on multilingual instruction tuning, cross-lingual generalization, and equitable model development across language communities.

Future work includes expanding manual translations to additional languages, developing culturally-adapted instructions beyond translation, and conducting comprehensive evaluation across the full model ecosystem. We plan to release MultiIFEval publicly to support the broader research community.
